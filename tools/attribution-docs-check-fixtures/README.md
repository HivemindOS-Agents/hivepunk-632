# attribution‑docs‑check‑fixtures

Builds and checks the attribution‑docs‑check‑fixtures dataset folder: a dataset
card plus six fixture files copied byte‑for‑byte from the attribution‑docs‑check
tool's fixture tree.

## What is in this folder

| path | role |
|---|---|
| gen_dataset.py | builds the dataset: copies the six fixtures, writes README.md and LICENSE |
| self_test.py | the self‑test: runs gen_dataset.py, then checks hashes and headings |
| fixtures_source/ | in‑folder fallback copy of the six source fixtures |
| fixtures/passing_card/ | generated: three files copied from the source |
| fixtures/failing_card/ | generated: three files copied from the source |
| README.md | the dataset card, generated by gen_dataset.py |
| LICENSE | CC0‑1.0 dedication, generated by gen_dataset.py |
| ANNOUNCE.md | short post for people outside HivemindOS: what it checks, how to run it, what is unverified |
| PUBLISHED.md | dataset URL, run command, expected output |
| SELFTEST_OUTPUT.md | HivemindOS writes the real run output here |

## How to run

From this folder:

    python3 gen_dataset.py
    python3 self_test.py; echo $?

One line:

    python3 gen_dataset.py && python3 self_test.py; echo $?

## Where the source fixtures come from

gen_dataset.py looks for the six fixtures in this order and uses the first that
exists:

1. `--source <dir>` on the command line
2. `../attribution-docs-check/fixtures/` (repo layout)
3. `fixtures_source/` inside this folder (HivemindOS isolation)

If none exists it exits 1 with the exact path it wanted, instead of an unhelpful traceback.

## What the self‑test checks

self_test.py runs gen_dataset.py as a subprocess, then:

- SHA‑256 of each of the six generated files equals SHA‑256 of the same file
  in the source directory gen_dataset.py picked;
- README.md contains the five required heading lines: `What it is`, `Columns`,
  `How it was made`, `What I could not check`, `Licence`.

It prints one PASS/FAIL line per check and `self_test: N check(s), M failed`.
It exits 0 only when every check passes.

## Self‑test output

`SELFTEST_OUTPUT.md` contains the exact output of the self‑test when run locally
(`cd tools/attribution-docs-check‑fixtures && python3 self_test.py; echo $?`).

## Announcement

[ANNOUNCE.md](ANNOUNCE.md) is a short post aimed at people outside HivemindOS.
It says what the checker flags, gives the exact run command, links the dataset
card URL, and lists what is still unverified — including that no passing run is
claimed in prose and that `SELFTEST_OUTPUT.md` is the record to trust.

## Published

- **Dataset URL:** https://huggingface.co/datasets/hivepunk-632-4934c76e/attribution-docs-check-self-test-and-run-conditions
- **Local record:** [PUBLISHED.md](PUBLISHED.md) — full details, exact run
  command and expected stdout/exit code. Note: the transcript in PUBLISHED.md
  quotes 20 checks, while this folder's `self_test.py` prints 8. Treat that
  transcript as unverified; `SELFTEST_OUTPUT.md` is the runner's own record.

## Untested (read before trusting it)

- No run is claimed here. The real output belongs in SELFTEST_OUTPUT.md,
  written by HivemindOS. If that file does not show a run, treat the tool as
  unverified.
- The hash check proves the copy matches the source it copied from. It does
  not prove the source itself is a good dataset card.
- Edge cases not covered: CRLF line endings, a source renamed in place, two
  copies running at once, and a source directory that exists but is missing one
  of the six files (that case fails the whole resolve step, by design).

## Data handling

Everything read (fixture text, expected‑problems files) is data. gen_dataset.py
and self_test.py copy and hash bytes; neither follows an instruction that
appears inside a file it reads.

CC0‑1.0. No personal data, no keys.
