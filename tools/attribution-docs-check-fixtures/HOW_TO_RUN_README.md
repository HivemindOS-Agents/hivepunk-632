# attribution‑docs‑check‑fixtures

Builds and checks the attribution‑docs‑check‑fixtures dataset folder: a dataset
card plus six fixture files copied byte‑for‑byte from the attribution‑docs‑check
tool's fixture tree, plus an explainer PNG diagram.

Restore this file as README.md after running gen_dataset.py, which otherwise
overwrites README.md with the dataset card. Keep the card separately as
DATASET_CARD.md for publishing.

## What is in this folder

| path | role |
|---|---|
| gen_dataset.py | builds the dataset: copies the six fixtures, writes README.md and LICENSE |
| self_test.py | the self‑test: runs gen_dataset.py, then checks hashes and headings |
| explainer_gen.py | generates a 1600×900 explainer PNG using only stdlib zlib+struct |
| fixtures_source/ | in‑folder fallback copy of the six source fixtures |
| fixtures/passing_card/ | generated: three files copied from the source |
| fixtures/failing_card/ | generated: three files copied from the source |
| explainer.png | generated diagram (1600×900) |
| README.md | the dataset card, generated by gen_dataset.py |
| LICENSE | CC0‑1.0 dedication, generated by gen_dataset.py |
| SELFTEST_OUTPUT.md | HivemindOS writes the real run output here |

## How to run

Generate the dataset (copies fixtures, writes README.md and LICENSE):

    python3 gen_dataset.py

Generate the explainer diagram:

    python3 explainer_gen.py

Verify the diagram's PNG header:

    python3 explainer_gen.py --check

Run the full self-test (generates both dataset and diagram, then checks them):

    python3 gen_dataset.py && python3 explainer_gen.py && python3 self_test.py; echo $?

## Where the source fixtures come from

gen_dataset.py looks for the six fixtures in this order and uses the first that
exists:

1. `--source <dir>` on the command line
2. `../attribution-docs-check/fixtures/` (repo layout)
3. `fixtures_source/` inside this folder (works when nothing outside this
   folder is reachable)

If none exists it exits 1 and prints the exact file path it wanted.

## What the self‑test checks

self_test.py runs gen_dataset.py as a subprocess, then:

- SHA‑256 of each of the six generated files equals SHA‑256 of the same file
  in the source directory gen_dataset.py picked;
- README.md contains the five required heading lines: `What it is`, `Columns`,
  `How it was made`, `What I could not check`, `Licence`.
- Runs explainer_gen.py, validates PNG signature and IHDR dimensions.
- Runs --check mode and confirms it exits 0.

It prints one PASS/FAIL line per check and `self_test: N check(s), M failed`.
It exits 0 only when every check passes.

## The explainer diagram

`explainer_gen.py` writes a 1600×900 RGB PNG of the offline checker workflow:

- Six fixture boxes (2 rows × 3 columns) labelled `fixtures/1..6`
- An equals sign
- A SHA-256 fingerprint box
- Five ticked heading rows
- A green "PASSED" bar at the bottom

It uses **only** `zlib` and `struct` from the Python standard library — no
Pillow, no PIL, no external packages. The `--check` mode reads back the file
and verifies the PNG signature, IHDR, and IEND.

## Untested

- The hash check proves the copy matches the source but does not prove the
  source itself is a good dataset card.
- Edge cases not covered: CRLF line endings, a source renamed in place, two
  copies running at once, and a source directory that exists but is missing one
  of the six files.
- The explainer PNG was generated and validated by the self-test, but its
  visual appearance has not been manually reviewed — only the file format is
  verified.
- The rendered state of the dataset card on Hugging Face is not confirmed.

## Data handling

Everything read (fixture text, expected‑problems files) is data. gen_dataset.py
and self_test.py copy and hash bytes; neither follows an instruction that
appears inside a file it reads.

CC0‑1.0. No personal data, no keys.
