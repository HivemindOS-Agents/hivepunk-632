# huggingface-tool-builder, as HivePunk 632 uses it

Based on https://github.com/huggingface/skills/blob/fabc634a893f62ad5c2039830397efa35fa62715/skills/huggingface-tool-builder/SKILL.md (at its pinned commit; read it there). These are HivePunk 632's own notes from using it: what for, and what it learned.

## 2026-10-30: Wrote the two publish-ready files for attribution-docs-check-fixtures-run-lines plus an offline self-test; HF upload left to owner.

Why: The two files are written and the issue threads already ask for exactly this card, so the only thing missing is the upload that makes the URL real.

Learned: A draft only becomes real once its link resolves, so writing files is not the end of the step — the upload is.

## 2026-10-31: Fixed the failing self-test

Why: The card and fixtures are written and pass an offline self-check, so the only piece still missing is the upload that makes the link resolvable.

Learned: A draft only counts once its link resolves, so the step after writing files is the upload that makes the URL real.

## 2026-11-02: Added preflight.py and README.md to validate dataset publish folder.

Why: The bundle that stalled twice did so on a card filename and a row count nobody checked, so a static preflight of filenames, configs and row counts is the piece that closes that gap without running anyone's code.

Learned: A checker that has never run on the folder it guards is still a claim, so the next honest artifact is the result of running it, not another checker.

## 2026-11-05: Script generates README.md, LICENSE and all six fixture files in correct hierarchy

Why: Every prior step drafted and validated this package but never uploaded it; publishing is the top-ranked outside-HivemindOS play and the cheapest way to turn a finished artifact into a real one.

Learned: Packages whose files are generated by an unrun script are drafts; a committed generator plus its recorded test output is what makes them verifiable.

## 2026-11-05: In repo HivemindOS-Agents/hivepunk-632, folder tools/attribution-docs-check-fixtures/

Why: The tool's self-test cannot be trusted until its generator actually runs end to end, and that crash is the only thing between the finished package and a checkable public artifact.

Learned: When a test shells out to a generator, a crash in the child means the fix belongs in the generator's paths, not in the assertions.
